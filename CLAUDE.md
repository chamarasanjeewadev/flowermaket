# Flowers.lk

Sri Lanka's online flower marketplace — connecting buyers with local florists and growers. Full product spec: `.superpowers/sdd/` — read it before large changes.

## Stack (fixed — do not substitute)

- **TanStack Start** (React 19, Vite, file-based routes) for all three apps
- **Turborepo + pnpm workspaces**
- **Supabase** (Postgres + Auth + Storage) — ap-south-1 (Mumbai)
- **Drizzle ORM** (`packages/db`) — schema is source of truth; hand-editing `migrations/` is forbidden
- **shadcn/ui + Tailwind v4** (`packages/ui` shared design system)
- **Cloudflare Workers** deploy target for all three apps
- **PayHere** primary payments (Phase 2); Stripe secondary

## Monorepo layout

```
apps/
  web/       Port 3000 — public buyer-facing marketplace (SEO-critical, locale path prefix)
  supplier/  Port 3001 — supplier/florist portal (noindex, bilingual toggle, no path prefix)
  admin/     Port 3002 — internal admin portal (noindex,nofollow, no path prefix)
packages/
  api/          Shared typed data layer: getEnv(), createDb(), tryCreateDb(), getUserRole(), constants, slug helpers
  auth/         Supabase auth helpers: createSupabaseServerClient(), hasRole()
  config/       Shared tsconfig.base.json
  db/           Drizzle schema (src/schema/*), createDb() client, drizzle-kit migrations
  integrations/ Third-party integrations: PayHere checkout types + formatCents()
  ui/           shadcn-style components + Tailwind globals
```

## Commands

```sh
pnpm install
pnpm build        # must run before typecheck on a fresh clone — generates routeTree.gen.ts per app
pnpm typecheck    # depends on ^build; never run before build on a fresh clone
pnpm test         # vitest (packages/api + packages/integrations)
pnpm dev          # all apps concurrently (turbo)
pnpm --filter @flowers/web dev   # single app

pnpm db:generate  # drizzle-kit generate (needs DIRECT_DATABASE_URL)
pnpm db:migrate   # drizzle-kit migrate  (needs DIRECT_DATABASE_URL)
pnpm db:seed      # insert categories; SEED_DEMO=1 also adds demo shop + products
pnpm db:studio    # drizzle-kit studio

pnpm deploy:web       # vite build + wrangler deploy for apps/web
pnpm deploy:supplier  # vite build + wrangler deploy for apps/supplier
pnpm deploy:admin     # vite build + wrangler deploy for apps/admin
```

## Key conventions

**Build before typecheck.** `routeTree.gen.ts` is generated by `vite build` (via the TanStack Start Vite plugin). On a fresh clone: `pnpm build` first, then `pnpm typecheck`. CI must order tasks the same way (turbo `typecheck` already `dependsOn: ["^build"]`).

**Money is integer LKR cents.** All `price`, `compareAtPrice`, `commissionRateBps` columns are `integer`. Never store floats for money. Use `formatCents(n)` from `packages/integrations` to produce PayHere's `"1234.56"` string.

**Bilingual columns.** Every user-visible text field comes in `*_en` / `*_si` pairs (e.g. `name_en`, `name_si`). Always provide the English value; Sinhala is nullable. The display layer falls back to `en` when `si` is null. Column naming convention: `nameEn` / `nameSi` in Drizzle schema → `name_en` / `name_si` in Postgres.

**Locale routing — web only.** `apps/web` uses a `/$locale` path prefix (`/en/…`, `/si/…`). The root `/` detects locale from cookie → Accept-Language → default `en` and redirects. `apps/supplier` and `apps/admin` use a cookie-based locale toggle with no path prefix.

**Lazy env access on Workers.** Cloudflare Workers evaluate module scope once per isolate, before per-request env bindings are injected. Always call `getEnv()` from `packages/api/src/env.ts` inside a request handler or server function — never at module top level. Same rule for `createDb()` / `tryCreateDb()`.

**Auth-disabled dev mode.** When `SUPABASE_URL` / `SUPABASE_ANON_KEY` are absent the session resolves to `{ kind: "auth_disabled" }` and auth redirects are skipped. This allows local UI development without a live Supabase project.

**No `any`, no untyped SQL.** End-to-end type safety is a hard constraint. Use Drizzle for all DB access; no raw SQL strings except inside migrations.

**Cloudflare connection settings.** Postgres client must be `{ max: 1, prepare: false }` — required for the Supabase transaction pooler in a stateless Workers environment.

## Schema at a glance

```
users           id (= auth.users.id), role (buyer|supplier|admin), email, phone, full_name, preferred_language
shops           id, owner_user_id → users, slug, shop_type (florist|grower), name_en/si, district, city,
                verification_status (unverified|pending|verified|rejected), commission_rate_bps, bank_details
categories      id, slug, name_en/si, sort_order, is_active
products        id, shop_id → shops, category_id → categories, slug, name_en/si, description_en/si,
                price (LKR cents), compare_at_price, stock_qty, lead_time_days,
                listing_type (retail|wholesale), min_order_qty, status (draft|active|paused|archived)
product_images  id, product_id → products, storage_path, alt_text, sort_order, is_primary
```

A `handle_new_user` trigger on `auth.users` inserts a row into `public.users` on signup.
